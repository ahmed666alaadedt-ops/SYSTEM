**Scope:** repository inventory, project instructions, both Godot projects, Android structure, scenes/autoloads, procedural world/building systems, character assets, geography integration, CI runs and production gaps.

## 1. Executive summary

The repository contains a substantial amount of source code and several successful automated Godot/Android workflows. It is not yet a completed open-world game or a finished 3D art pipeline.

**The main finding for the requested building work:** do not start creating new production buildings yet. The modern city system already creates many placeholder building masses and road/district meshes. The current blocker is not a lack of building-spawn code; it is the absence of approved, detailed building assets, verified real-world geographic data integration, finished entrances/interiors, and a validated end-to-end production pipeline.

The canonical project and prototype remain separate and must be preserved.

## 6. Modern world map and city/building audit

### Existing procedural foundation

`modern_continent_manager.gd` creates a connected procedural terrain prototype with terrain mesh/collision, coast/beach treatment, water features and sampled height data.

`modern_world_region_manager.gd` defines fourteen city names:
New York, London, Paris, Baghdad, Moscow, Cairo, New Delhi, Guangzhou, Seoul, Tokyo, Singapore, Sydney, Rio de Janeiro and Johannesburg.

It defines eight district categories per city:
Downtown, OldTown, Residential, Commercial, Industrial, University, Waterfront and GreenBelt.

It also creates or coordinates:
- City anchors and civic plazas.
- City-identity landmark silhouettes.
- Procedural building masses using `MultiMesh` box geometry.
- District road strips, sidewalks and crosswalk meshes.
- Street furniture, services and visual transport hubs.
- Rural settlement prototypes.
- Transport corridor and lighting managers.
- Baghdad landmark structures, traffic and incident prototypes.

### Building findings

- The generated district building masses are box meshes with district-specific height ranges and material palettes. They are efficient blockout geometry, not detailed architecture.
- City identity landmarks are currently assembled from primitive box/cylinder geometry.
- The older `world_manager.gd` still calls legacy road, city-building, tree, skyline, forest, mountain and water generation in addition to the newer continent/region layer. This creates a potential duplicate/overlap and ownership risk that requires visual inspection before either layer is changed.
- The modern-world completion tracker explicitly leaves distinctive architecture, complete streets, functioning facilities, interiors, transport and performance acceptance unchecked.
- The current modern city code does not provide a finished building kit with reviewed facades, windows, doors, balconies, rooflines, signs, storefronts, interior furnishing and full access/navigation.

### Building interiors

- `fantasy_city_interior_expansion.gd` is registered as an autoload and generates enterable interiors for a limited list of fantasy kingdom facilities/homes.
- This is a fantasy-world-specific first pass; it does not establish completed modern-world building interiors.
- No equivalent completed, verified interior pipeline was found for modern cities, historical settlements or Greed Island.

**Conclusion:** existing building geometry must be catalogued and visually inspected first. New production buildings should wait until the existing procedural blocks, city anchors, collisions, entrances, interiors and duplicate legacy generation are reconciled.

## 7. Real-world geography — critical integration gap

The current canonical decision in `REAL_EARTH_GEOGRAPHY_AND_NPC_LIFE.md` is a real-Earth modern world, initially built from a real Baghdad region and licensed/versioned geospatial data.

The current repository state is only a seed:
- `data/geography/real_world_registry.json` contains one provisional Baghdad/Iraq geographic anchor.
- It does not contain Baghdad road graphs, district polygons, elevation raster, building footprints, bridges or landmark datasets.
- The registry marks the country as `seed_only` and Baghdad as `geographic_anchor_only`.
- `real_world_geography_manager.gd` contains WGS84/ECEF and regional-coordinate conversion logic.
- At the inspected baseline commit, the manager was registered as an autoload but its city-position conversion API had no runtime caller. A follow-up change now connects the Baghdad city anchor in `modern_world_region_manager.gd` to `SystemRealWorldGeography.get_city_world_position("city_baghdad")`. This is only a single geographic anchor, not a real Baghdad map.
- The current fourteen-city `CITY_DATA` list in `modern_world_region_manager.gd` uses hard-coded fictional `Vector2` centers on the procedural continent. It does not yet derive city positions from the WGS84 registry.

The earlier fictional-continent map is explicitly described as a prototype/reference layer in `MODERN_WORLD_MAP_EXPANSION.md`. It must not be called the finished real-Earth map.

**Required before geographic building production:** complete a licensed Baghdad regional data pack and connect the registry → regional projection → terrain/roads/building footprints → collision/navigation → Godot region scene pipeline. Do not invent coordinates or real city features.

## 8. Four-world status

The canonical `world_manager.gd` defines four world roots and lazy-loads each world on first entry:
1. Modern realistic world.
2. Historical/civilizations world.
3. Fantasy world.
4. Greed Island.

The automated missing-mesh diagnostic iterates the four world IDs, and the latest Godot project validation workflow completed successfully.

However, the four worlds are not production-complete:
- Historical and fantasy environments are largely procedural primitive/mesh foundations, with limited landmark/settlement systems.
- Greed Island is explicitly marked `admin_test_mode = true` and `combat_enabled = false`; its current manager describes creatures/landmarks as showcase/display/exploration content. It is not a complete combat/gameplay world.
- Greed Island includes a Babylon Tower landmark and other display-only structures; world-specific visual/lore review is still required.
- Shared systems and world-specific gameplay require further end-to-end tests.

### Specification conflict
`SYSTEM_MASTER_VISION.md` and root `AGENTS.md` define four total worlds: modern, historical/civilizations, fantasy, and Greed Island.
`SYSTEM_WORLD_MASTER_SPEC.md` uses the phrase “four independent fantasy worlds” while separately describing a main realistic world. This wording conflicts with the current four-total-world decision and should be corrected in a documentation-only review before it causes implementation drift.
